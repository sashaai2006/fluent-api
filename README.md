# ExprFlow

**Библиотека композиционного описания вычислений с автоматическим параллельным исполнением на пуле потоков.**

Курсовой проект по дисциплине «Параллельное программирование» (объединение задач №1 «Декомпозиция и диспетчеризация задач» и №10 «API для композиционного описания вычислений»).

---

## Для чего нужен

позволяет описывать вычисления **декларативно** — цепочкой комбинаторов — а исполнять их **автоматически параллельно**. Пользователь пишет *что* считать, а не *как* распараллеливать: параллелизм выводится из структуры самого выражения.

```cpp
auto computation = Expression
    .Value(2, 3)
    .Every(
        [](int a, int b) { return std::pow((a + b) / 2.0, 2); },
        [](int a, int b) { return std::pow((a - b) / 2.0, 2); },
        [](int a, int b) { return std::max(a, b); },
        [](int a, int b) { return std::min(a, b); })
    .Then([](double halfSum, double halfDiff, int mx, int mn) {
        return (halfSum + halfDiff) * mx / mn;
    });

double result  = computation.Eval();              // синхронно
auto future    = computation.EvalAsync();         // асинхронно
```

Типичные сценарии применения:

- параллельные конвейеры обработки данных (`Map` / `FlatMap` / `Fold`);
- независимые ветки вычислений от общего входа (`.Every()`);
- асинхронные вычисления с продолжениями (`EvalAsync`).

## Как это работает

Архитектура — четыре слоя:

1. **API-слой.** Комбинаторы (`.Value()`, `.Every()`, `.Then()`, `.Map()`, `.Fold()`, …) строят ленивое выражение — ничего не вычисляется до вызова `Eval`.
2. **Декомпозиция.** Дерево выражения превращается в направленный ациклический граф (DAG) зависимостей: узел = элементарная операция, дуга = «результат A нужен на входе B». Ацикличность гарантирована построением: узел может зависеть только от ранее созданных узлов.
3. **Диспетчер.** Узлы с нулевым счётчиком невыполненных зависимостей («созревшие») раздаются рабочим потокам пула; при завершении узла счётчики потомков атомарно уменьшаются, вновь созревшие узлы ставятся в очередь. Параллелизм двух уровней: между независимыми ветками графа и внутри операций над коллекциями (`Map` / `Fold` при ассоциативной операции).
4. **Асинхронный фасад.** `Eval()` — синхронный результат; `EvalAsync()` — запуск без блокировки вызывающего потока с результатом через `std::future`.

Ключевые проектные решения:

- **Двухфазная модель**: граф строится однопоточно, затем фиксируется вызовом `seal()` и в фазе исполнения иммутабелен по топологии — чтение структуры не требует блокировок, синхронизируются только счётчики (`std::atomic`) и очередь готовых узлов.
- **Type erasure на границе графа**: типы входов/выходов узлов живут в замыканиях лямбд, граф хранит однородные `void()`-операции; корректность типов проверяется шаблонами на этапе компиляции цепочки.
